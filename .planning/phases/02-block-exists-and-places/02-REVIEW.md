## Warnings

### WR-01: Block translation key duplicated as a hand-written literal instead of using the type-safe overload

**File:** `src/client/java/transitreport/client/JollyalchemyTransitReportDataGenerator.java:37`
**Issue:** `TransitReportLanguageProvider.generateTranslations` builds the block's translation key by string concatenation:
```java
translationBuilder.add("block." + JollyalchemyTransitReport.MOD_ID + ".transit_chart", "Transit Chart");
```
`FabricLanguageProvider.TranslationBuilder` (verified in `fabric-data-generation-api-v1-12.4.0` sources) exposes a `default void add(Block block, String value)` overload that derives the key from `Block#getDescriptionId()`. The current code instead hand-duplicates the registry path `"transit_chart"`, which is defined once already in `TransitReportBlocks` (`JollyalchemyTransitReport.id("transit_chart")`). If the block's registry name is ever renamed, this literal will silently go stale — no compiler error, just a missing/incorrect in-game name, and only discoverable by looking at the tooltip in-game. This is exactly the kind of desync the "avoid premature duplication" spirit of the project's conventions is meant to prevent.
**Fix:**
```java
translationBuilder.add(TransitReportBlocks.TRANSIT_CHART, "Transit Chart");
```
(The `"text.<mod-id>.refreshing"` key on the line above must stay a literal — no Java object exists yet to derive it from at this phase.)

## Info

### IN-01: Unmodified Fabric template log message left in production init path

**File:** `src/main/java/transitreport/JollyalchemyTransitReport.java:24`
**Issue:** `LOGGER.info("Hello Fabric world!")` is the default string generated by the Fabric example-mod template and was not customized for this project. It will show up verbatim in every server/client log on mod load, which is confusing noise for a mod named "Human Design Transit Display."
**Fix:** Replace with a message specific to this mod, e.g. `LOGGER.info("Initializing Human Design Transit Display");`, or remove the line entirely if init-time logging isn't wanted yet.

### IN-02: Unexplained magic number for block hardness

**File:** `src/main/java/transitreport/TransitReportBlocks.java:27`
**Issue:** `.strength(1.5F)` has no comment indicating why `1.5` was chosen (vs. e.g. matching a vanilla block it's modeled after, like the furnace's `3.5F`/`3.5F`). Not a bug, but a future maintainer (including future-you) has no way to tell if this value is intentional or a placeholder.
**Fix:** Add a short comment noting the rationale (e.g. "borrowed from X" or "arbitrary, tune later"), or extract to a named constant if more block-tuning values are added in a later phase.
