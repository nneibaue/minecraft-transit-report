## Edge cases this plan covers

- **Stale CDN after the push:** Task 3 blocks the reboot until the raw URLs hash-match origin/main. Rebooting early would download the old bytes and make the proof read as failed.
- **GitHub unreachable at boot:** the optional offline reboot in Task 4 exercises startup.lua's fallback. With "skip-offline", the fallback stays judgment-verified by reading startup.lua's fetch branch.
- **startup.lua does not update itself (D-19):** device A keeps the startup.lua it installed from 4df2021. Task 5 accepts any startup.lua blob from origin/main's history and records which one under STARTUP_LUA_ON_A. The README tells admins to re-run the wget line to pick up a new startup.lua.
- **A payload that changes nothing:** Task 1 requires both Lua files to differ from origin/main before commit. Otherwise "up to date" on reboot would prove nothing.
- **A short passphrase token that collides with repo text:** Task 5's scan reports paths only. A hit means a more distinctive passphrase is needed (D-15).
