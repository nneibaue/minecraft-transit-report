## Artifacts this phase produces (this plan)

- `DEBUG`: a Lua local in `base/chat.lua` and `turtle/client.lua`, set to `fs.exists("debug")` at program start.
- `dbg(...)`: a Lua local function in both files. It joins its arguments with tostring and single spaces, prints the line through `log("DEBUG", line)`, and appends it to `debug.log`.
- The marker `debug` (a file or folder in the device root) and the log file `debug.log` (device root).
- The debug line formats: `chat event: user=… text=… uuid=… hidden=… extra=…`, `say: to=… prefix=… text=…` and `say returned: ok=… err=…` in chat.lua; `recv: <frame>` and `result: <frame>` in client.lua.
- chat.lua's `chat` branch gains the locals `user, text, uuid, hidden` and the `$` restore line. client.lua's `session` gains the local `json`.
- `tests/test_device_lua.py` gains:
  - the regex constant `DEVICE_OUTPUT_CALL`;
  - the tuple `DEBUG_FILES`;
  - the helper `code_lines()`;
  - `test_chat_restores_the_dollar_ap_strips`;
  - `test_device_output_never_shows_the_token`;
  - `test_debug_is_a_marker_file`.
- `bridge/agent.py`: one new `SYSTEM_TEMPLATE` Rules bullet, containing the phrases "one or two sentences" and "plain ASCII".
- Check markers: `LUA_PARSE_OK`, `RAW_MATCH_OK`, `PROMPT_LINE_OK`, `HARNESS_UNTOUCHED_OK`.

## Edge cases this plan covers

- **AP build that does not strip:** the restore adds `$` only when the hidden text does not already start with `$`, so `$robot …` never becomes `$$robot …`. The docs page describes a newer AP, and the jar is the authority.
- **Every `$` removed:** `$robot costs $5` arrives as `robot costs 5`. Only the leading prefix comes back. The bridge only needs the prefix.
- **Stale raw GitHub copy:** Task 1's check fetches only chat.lua, so client.lua's raw URL is first fetched after its own push, in Task 4. Fetching client.lua in Task 1 would pin the old file in the ~5-minute CDN cache.
- **`fs.open` returning nil (disk full):** `dbg` skips the write rather than raising inside the session.
