# Quick task 260919-64m — bridge.lua design decisions (locked)

User request (verbatim intent): "I have balustrade cobblestone bridge pieces in ATM9. I want a
CC:Tweaked turtle equipped with bridges to build a bridge for me outward. When it runs out of
pieces, it comes back to the start. I will have it start on a vitreous moonstone from Blue
Skies. When it finds a biome, I want it to place a block on the side with a sign that labels
that biome."

The user is not available for questions. The decisions below resolve every gray area. Do not
revisit them; implement them.

## Deliverables
1. `turtle/bridge.lua` — new script, same style as `turtle/tunnel.lua` and `turtle/crater.lua`
   (header comment with setup/usage, `Config` block at top, state file, push/clear move
   helpers, `keyWatcher` + `parallel.waitForAny`, `print` progress lines, `error()` with a
   human instruction when stuck).
2. `turtle/README.md` — add a `bridge.lua` row to the Scripts table and a `## bridge.lua setup`
   section (equipment, inventory, how to start, reset/status, Q).

## World / mod facts to code against
- ATM9, Minecraft 1.20.1 Forge, CC:Tweaked. Lua only.
- Bridge piece item/block id looks like `mcwbridges:balustrade_cobblestone_bridge` (Macaw's
  Bridges). Match by name containing `bridge` (config `BRIDGE_MATCH = "bridge"`). Bridge blocks
  float (no support needed) and take their horizontal `facing` from the placer, i.e. the
  turtle's heading at `placeDown()` time. Bridge pieces are therefore ONLY ever placed while
  the turtle is facing "out".
- Start block: `blue_skies:vitreous_moonstone`. Do not hardcode: on first run record
  `inspectDown().name` as `homeBlock` in state (warn if it does not contain `moonstone`, but
  continue).
- Biome comes from an Advanced Peripherals **Environment Detector turtle upgrade**:
  `peripheral.find("environmentDetector") or peripheral.find("environment_detector")`;
  `getBiome()` returns a string like `minecraft:plains` (tolerate a table with `.name`/`.id`
  or `[1]`). If no detector is found: print what to equip and stop (do not build unlabeled).
- The other equipment side is a pickaxe (needed to clear obstacles and for the facing probe).
- `turtle.place(text)` / `turtle.placeDown(text)` write the text onto a sign being placed;
  `\n` separates lines; 4 lines of ~15 chars.

## Geometry
- The turtle starts sitting on TOP of the moonstone, facing the direction to build. That
  cell (deck+1 above the moonstone) is **home**, distance 0. The bridge deck is at the
  moonstone's level; the turtle flies at deck+1 and uses `placeDown()`. Piece 1 goes at
  distance 1, directly in front of the moonstone.
- `WIDTH` config (default 1). Extra lanes are to the RIGHT of lane 0. For each column: place
  lane 0, sidestep right (turnRight, forward, turnLeft) for each further lane, place, then
  return to lane 0 and advance one block. Bridge pieces are always placed facing out.
- Per column, at the deck spot below the turtle:
  - already a bridge piece → skip (counts as built; makes reruns idempotent);
  - air / water / lava → `placeDown()` a bridge piece;
  - other solid block (terrain) → leave it unless `REPLACE_TERRAIN = true`, in which case
    `digDown()` then place. Never dig down otherwise.
- Obstacles at turtle level (deck+1) in the path: dig them (tunnel.lua `clear`/`push`
  pattern, with attack for mobs, bedrock/stubborn give-up). Never dig the block below,
  never dig bridge pieces, the home block, signs, or marker blocks.

## Biome markers
- Read the biome once per column (after placing the bridge for that column, before
  advancing). If it differs from `state.lastBiome` (including the very first column, where
  lastBiome is nil) → place a marker. Then set `state.lastBiome`.
- Marker goes on `MARKER_SIDE` (config, default `"right"`) beside the outermost lane on that
  side, at deck level, with a standing sign on top of it (sign at deck+1, so it stands next to
  a walking player's legs, text facing the bridge). Sequence with turtle at deck+1 over the
  edge lane, facing out: turn toward the marker side; `forward` 1 (clearing obstacles); if
  the block below is air/liquid → select marker block, `placeDown()` (if a solid block is
  already there, use it as the marker); `up` 1; if the cell below is now empty → select
  sign, `placeDown(signText)` (a standing sign lands on the marker with text facing the
  turtle's back, i.e. the bridge); turn around; `forward` 1; `down` 1; turn to face out.
  Result: the turtle is back over the edge lane at deck+1 facing out.
- If a sign already occupies the sign cell (rerun over an existing bridge) skip placing.
- If a marker or a sign is needed and none is in inventory → do NOT update lastBiome; go home
  and report ("out of signs" / "out of marker blocks"), so the biome gets marked on the next
  run.
- Sign text: prettify the id (`minecraft:dark_forest` → `Dark Forest`, `blue_skies:x_y` →
  `X Y`), word-wrap into lines of ≤15 chars, max 4 lines; if a line is free, last line is
  `<dist>m out` (distance from home). Join with `\n`.

## Inventory (identified by name, no fixed slots)
- bridge pieces: name contains `BRIDGE_MATCH`.
- signs: name contains `sign`.
- fuel: any slot where `turtle.refuel(0)` returns true (coal, charcoal, etc.).
- marker blocks: config `MARKER_MATCH` (default nil). nil → the first stack that is none of
  the above (e.g. cobblestone, stone bricks, a fence post block). Print which item is being
  used as the marker at startup.
- Re-scan inventory each time a kind is needed (`findSlot(kind)` returning the first
  matching slot, or nil).

## Fuel
- `FUEL_LOW = 200`: below this, `refuel` from any fuel stack (one item at a time up to
  `FUEL_TARGET = 2000`). "unlimited" fuel skips all checks.
- Before each column: if fuel < `dist + FUEL_MARGIN (50)` and refuelling cannot fix it → go
  home. Never strand the turtle.

## Return-home triggers (all print a one-line reason)
1. No bridge pieces left (checked before each column).
2. Fuel margin (above).
3. `MAX_LENGTH` (config, default 0 = unlimited) reached.
4. Marker/sign needed but not carried.
5. Q pressed (finish the current column first).
Going home: face "back", `push` forward `dist` times along the bridge at deck+1, then turn to
face "out" again so a refill + rerun needs no repositioning. At dist 0 verify `inspectDown`
name == `homeBlock`; if not, search forward/back one block for it (mirrors quarry's
self-correction) and otherwise `error()` with an instruction.
Final line: pieces placed this run, total bridge length, signs placed this run, "Refill and
run again."

## State file `bridge_state.txt` (textutils.serialize)
`{ dist, lane, heading ("out"|"back"|"left"|"right"), built, lastBiome, homeBlock, fOut,
placed, signs }`. Save immediately before AND after every move/turn that changes it (crater
pattern), so a reboot resumes. `fOut` = the world `facing` of a bridge piece as read back via
`inspectDown().state.facing` right after the first successful placement (nil if the block has
no facing property).

## Startup / resume
- `bridge reset` deletes the state file. `bridge status` prints the state and exits.
- No state file → fresh start: assume at home (dist 0, lane 0) facing out; record homeBlock.
- State with dist == 0 → at home facing out (the script always leaves it that way); travel
  out to `built` along the bridge and continue.
- State with dist > 0 (rebooted mid-bridge) → heading is unknown because a turtle cannot
  sense its facing. Recover with a probe: select a bridge piece, `placeUp()`, read
  `inspectUp().state.facing`, `digUp()`. Compare with `fOut` using the ring
  north→east→south→west to work out whether the turtle currently faces out/back/left/right,
  then turn to face out and carry on. If there is no piece to probe with, or no facing data,
  print "Put me back on the moonstone facing the bridge and run `bridge reset`" and stop.
  If `lane` > 0 after recovery, sidestep back to lane 0 first.
- While travelling out: stop early and start building if the deck below is neither a bridge
  piece nor a solid block before reaching `built` (set built = dist); at `built`, if the deck
  below is already a bridge piece, keep going (someone extended it by hand).

## Non-goals
No GPS, no multi-turtle, no chest refilling, no turning corners. Keep it one file, no
speculative abstractions.
